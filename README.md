# 线性代数知识图谱：BERT + BiLSTM-CRF 实体识别 + BiLSTM 关系抽取

从零构建一个线性代数领域知识图谱：先人工设计本体并整理种子三元组，再用远程监督自动标注语料，训练实体识别（NER）和关系抽取（RE）模型，从新文本中抽取三元组，最后用规则推理补全，导出到 Neo4j 并生成交互式可视化页面。

```
种子三元组 + 教材句子 ──远程监督──▶ BIO/关系标注语料 ──▶ BiLSTM-CRF（NER）
                                                      └─▶ BiLSTM 关系分类（RE）
新文本 ──NER──▶ 实体 ──实体链接──▶ 实体对 ──RE──▶ 候选三元组 ──过滤──▶ 合并 ──规则推理──▶ Neo4j / 可视化
```

## 2. 语料与标注（远程监督）

- **模板句**：每种关系有 4–7 个句式，用每条种子三元组填充，并随机替换别名、加句首修饰语。
- **教材句**：[data/natural_sentences.txt](data/natural_sentences.txt)，125 句人工编写的教材风格句子。
- **负例句**：在没有关系的实体对上生成的句子，标签为 NA。
- **自动标注**：
  - 实体：用词典做"全局最长优先"匹配，得到 BIO 标签。
  - 关系：句中每个有序实体对，如果在种子三元组里就标对应关系，否则标 NA。

为了让测试结果有意义、不是在背答案，测试集专门做了三种留出：

| 留出方式 | 测试什么 |
|---|---|
| 12 个实体完全不出现在训练集（如：反对称矩阵、楚列斯基分解、舒尔定理） | NER 能否识别没见过的实体 |
| 53 条三元组只出现在测试集 | 能否从文本中抽出图谱里没有的三元组 |
| 每种关系的最后一个句式只用于测试 | 对没见过的表达方式能否泛化 |

最终得到训练集 1273 句、验证集 160 句、测试集 681 句。

## 3. 模型

- **NER：BiLSTM-CRF**。逐字输入 → 双向 LSTM → 线性层 → CRF（自己实现的前向算法和维特比解码），BIO 标注 5 类实体。
- **关系抽取：BiLSTM 分类器**。逐字表示，加上到头、尾实体的相对位置向量和实体标记 → 双向 LSTM → [最大池化，头实体向量，尾实体向量，实体类型向量] → MLP → 10 类（9 种关系 + NA）。预测时屏蔽不符合头/尾实体类型约束的关系。
- **两种输入表示做对比**：
  - `char`：随机初始化、可训练的字向量。
  - `bert`：冻结的 `bert-base-chinese` 最后一层隐向量，每个字取对应位置的向量。

## 4. 实验结果（测试集）

| 指标 | char + BiLSTM | BERT + BiLSTM |
|---|---|---|
| NER 实体级 F1（全部） | 0.802 | **0.934** |
| NER 召回率：未见过的实体 | 0.537 | **0.816** |
| NER F1：教材句 | 0.733 | **0.839** |
| RE micro-F1（给定正确实体） | 0.848 | **0.862** |
| RE micro-F1：教材句 | 0.472 | **0.535** |
| 端到端三元组 F1（NER → 链接 → RE） | 0.626 | **0.771** |
| 留出三元组召回 | 44/53 | **50/53** |

要点：
- **BERT 的提升主要在 NER 泛化上**：没见过的实体召回率从 0.54 提升到 0.82。字向量模型遇到训练集没出现过的字（如"楚""舒"）基本无能为力，BERT 预训练过的字表示能弥补这一点。
- **教材句上的关系抽取明显更难**（F1 约 0.5）：
  1. 训练集里的教材句只有 57 句，大部分训练数据是模板句。
  2. 远程监督假设"种子里有关系的实体对，在句子里就表达了这个关系"，这对教材句并不总是成立，测试标签本身就有噪声。
- 各关系里 `depends_on`（定义依赖）最难（F1 0.72），因为它的表达方式最多样。

完整指标（每类实体、每种关系、混淆对）见 `outputs/{char,bert}/metrics.json`。

## 5. 抽取新三元组 + 规则推理

`build_kg.py` 用端到端 F1 更高的模型（BERT 版）处理两类文本：
- **教材句**：只补全已知实体之间的关系。
- **[data/new_text.txt](data/new_text.txt)**：包含词典里没有的实体，允许发现新实体。新实体要通过质量过滤：至少 3 个字、不含"的"、不是已知实体名的片段。

只有置信度 ≥ 0.95 的三元组才会并入图谱。

**发现了 14 个新实体**，包括格拉姆矩阵、范德蒙德行列式、希尔伯特空间、循环矩阵、托普利茨矩阵、正规矩阵、伪逆矩阵、条件数、希尔伯特矩阵、吉文斯旋转矩阵和雅可比迭代法。**并入图谱的新三元组有 27 条**，例如：

```
(格拉姆矩阵, 上位概念, 半正定矩阵)      (希尔伯特空间, 上位概念, 内积空间)
(吉文斯旋转矩阵, 上位概念, 正交矩阵)    (伪逆矩阵, 求解方法, 奇异值分解)
(条件数, 定义依赖, 奇异值)              (线性方程组, 求解方法, 雅可比迭代法)
(特征方程, 定义依赖, 行列式)            (西尔维斯特判据, 定理涉及, 实对称矩阵)
```

人工检查这 27 条，大部分正确，约 5 条偏宽泛或类型不准。例如"豪斯霍尔德变换"被识别成了定理（应为方法），"楚列斯基分解作用于矩阵"不如"作用于正定矩阵"准确。所有候选三元组及置信度见 `outputs/kg/extracted_candidates.tsv`，**实际使用前应人工审核**。

**规则推理**一共推出 140 条三元组，详见 `outputs/kg/inferred_triples.tsv`：

| 规则 | 内容 | 推出数量 |
|---|---|---|
| R1 | 传递：A is_a B，B is_a C ⇒ A is_a C | 86 |
| R2 | 性质继承：A is_a B，B 具有性质 P ⇒ A 具有性质 P | 47 |
| R3 | 等价对称 | 3 |
| R4 | 等价替换（只用于矩阵类实体）：X 具有 P，P ⇔ Q ⇒ X 具有 Q | 4 |

例子：由（希尔伯特矩阵 is_a 正定矩阵）和（正定矩阵具有特征值全为正），推出"希尔伯特矩阵的特征值全为正"。R4 只用于矩阵类实体，因为"正定性 ⇔ 特征值全为正"只对矩阵成立，不加这个限制会推出"内积具有特征值全为正"这种错误结论。

**最终图谱**：173 个实体，429 条三元组（种子 262 + 模型抽取 27 + 规则推理 140）。

### 导入 Neo4j（macOS，已实测）

前提是装好 JDK 21：
```bash
brew install openjdk@21
```
然后一条命令完成全部步骤：
```bash
./neo4j_setup.sh
```
脚本会依次：
1. 从 Neo4j 官方地址下载社区版 2026.10.2 和 cypher-shell 到 `.tools/`，并校验 SHA256；
2. 首次运行时随机生成本地数据库密码，保存在 `.neo4j.env`（仅本人可读）；
3. 启动 Neo4j，清掉本图谱的旧节点后重新导入 `outputs/kg/neo4j_import.cypher`；
4. 打印各类型实体数和各来源的三元组数用于校验（应为 173 个实体；种子 262、推理 140、抽取 27 条三元组）。

> 为什么不直接 `brew install neo4j`：在 Homebrew 5.0.12 上安装 cypher-shell 会报 `undefined method '[]' for nil`，所以改为直接使用官方压缩包。升级 Homebrew 后用 brew 安装也可以。

导入后在浏览器打开 http://localhost:7474 ，用户名 `neo4j`，密码见 `.neo4j.env`。停止服务：
```bash
./neo4j_setup.sh stop
```

图谱在 Neo4j 中的结构：
- **节点标签**：直接用中文类型，即 `概念`、`定理`、`性质`、`运算`、`方法`，Neo4j Browser 会给每种类型自动分配不同颜色。属性有 `name`、`type`、`source`，以及 `kg='linear_algebra'`（用于整体清除和重新导入）。
- **关系类型**：直接用中文，即 `上位概念`、`组成部分`、`定义依赖`、`具有性质`、`等价`、`求解方法`、`作用对象`、`得到结果`、`定理涉及`。属性有 `relation`（英文名）、`source`（seed / extracted / inferred），以及 `score`、`rule`、`via`。
- **单独重新生成导入脚本**：运行 `python3 kg/export_neo4j.py`，它直接读取 `kg.json`，不需要 PyTorch。

示例查询：
```cypher
// 查看全部实体和关系（173 个节点、429 条关系）
MATCH (n {kg:'linear_algebra'}) OPTIONAL MATCH (n)-[r]->(m) RETURN n, r, m

// 正定矩阵 2 跳以内的子图
MATCH p=(:概念 {name:'正定矩阵'})-[*1..2]->() RETURN p

// 正定矩阵的全部上位概念（含推理出的传递关系）
MATCH (:概念 {name:'正定矩阵'})-[:上位概念*]->(b) RETURN DISTINCT b.name

// 正定矩阵具有的性质，以及每条来自种子还是规则推理
MATCH (:概念 {name:'正定矩阵'})-[r:具有性质]->(p) RETURN p.name, r.source, r.rule

// 只看某一种关系，例如所有"定理涉及"
MATCH p=(:定理)-[:定理涉及]->() RETURN p

// 模型从新文本中发现的实体及其关系
MATCH (a {kg:'linear_algebra', source:'extracted'})-[r]->(b) RETURN a.name, type(r), b.name, r.source
```

**在 Neo4j Browser 中显示名字**：查询结果出来后，点击右侧 Results overview 里的每个类型标签（概念、定理……），在 Customize Style 中把 Size 调大到中间档。节点太小时名字会被隐藏，Caption 默认就是 `name`。这个样式会保存在浏览器里，只需设置一次。

**和 `kg_view.html` 的区别**：Neo4j Browser 是通用的查询工具，适合用 Cypher 查询、做多跳推理和筛选子图；`kg_view.html` 是专门为这个图谱做的展示页面，带图例、按来源/关系筛选、搜索，节点大小随连接数变化，推理边用虚线表示。看全貌、做演示时用 HTML 页面更直观，需要查询和分析时用 Neo4j。

## 8. 局限与可改进方向

- **语料规模小、以模板句为主**：可以接入真实教材或讲义文本，并人工标注一批句子作为干净的测试集。
- **远程监督标签有噪声**：可以加多实例学习（MIL）、句子级注意力，或用 LLM 辅助校对标签。
- **BERT 是冻结的**：微调 BERT 或换成 `chinese-roberta-wwm-ext` 预计还能提升。
- **其他方法**：
  - 关系抽取可以试联合抽取（如 CasRel）或基于 LLM 的抽取，和 BiLSTM 对比。
  - 新实体的类型判断还不够准，可以加实体类型分类器，或利用"……矩阵""……分解"这类后缀规则。
