# GraphRAG 数学问答

在线性代数知识图谱上做检索增强问答：把问题里的术语链接到图谱实体，检索相关子图，转成文字后交给大模型作答。并和"不检索""向量 RAG"做对比实验。

```
问题 ──实体链接──▶ 图谱实体 ──子图检索──▶ 候选事实 ──向量重排──▶ 前 12 条事实 ─┐
  └──────────────── 向量检索教材句子（对照组）──────────────────────────────┤
                                                                           ▼
                                                             提示词 ──▶ 云端大模型 ──▶ 回答
```

## 做法

| 步骤 | 实现 | 位置 |
|---|---|---|
| 实体链接 | 词典（含别名）全局最长匹配；没链接到具体实体时，用问题和实体名的向量相似度兜底 | `kgqa.py` `KnowledgeGraph.link` |
| 子图检索 | 实体两两之间的最短路径（3 跳以内）必留；再加每个实体的一跳邻居。图谱里已经物化了规则推理出的继承关系，所以一跳就能拿到多跳结论 | `Retriever.graph_search` |
| 枢纽实体处理 | "矩阵""向量"这类连着 30 条以上边的实体不单独展开，只经过它们的事实最多保留 3 条 | 同上 |
| 重排 | 用 bge-small-zh 计算每条事实和问题的相似度，保留最相关的 12 条 | 同上 |
| 事实转文本 | 每种关系一个中文模板，例如 `(格拉姆矩阵, has_property, 可对角化)` → "格拉姆矩阵具有性质：可对角化" | `VERBALIZE` |
| 向量 RAG（对照） | 文档库是 142 句教材风格句子，取相似度最高的 5 句 | `Retriever.vector_search` |
| 大模型 | 通过 OpenAI 兼容接口调用云端模型，温度 0 | `llm.py` |

流程是用普通 Python 写的，没有用 LangChain / LangGraph：整个流程是一条直线，没有分支和循环，不需要编排框架。

## 运行

1. 配置大模型：把项目根目录的 `.llm.env.example` 复制为 `.llm.env`，填上接口地址、API key 和模型名。`.llm.env` 已被 `.gitignore` 排除。
2. 提问：
   ```bash
   .venv/bin/python qa/ask.py "格拉姆矩阵一定可对角化吗？"
   ```
   会显示链接到的实体、检索到的每条事实（来源、检索原因、相似度）和回答。加 `--compare` 可以并排对比四种方案；不带问题则进入连续提问模式。
3. 评测：
   ```bash
   .venv/bin/python qa/evaluate.py
   ```
   先做检索并缓存，再逐题调用大模型；中断后重跑会接着做。结果在 `outputs/qa/`。

## 评测设置

- **题目**：[data/qa_questions.tsv](../data/qa_questions.tsv)，108 道人工编写的判断题和单选题，可以自动判分。选项顺序按固定随机种子打乱。
- **四类题**：

  | 类别 | 数量 | 含义 | 例子 |
  |---|---|---|---|
  | 图谱直接可答 | 28 | 图谱里有直接对应的三元组 | 楚列斯基分解适用于哪一类矩阵？ |
  | 需多跳/推理 | 29 | 要用到推理出的继承或传递关系 | 希尔伯特矩阵的特征值全为正吗？ |
  | 陷阱题 | 27 | 答案多为"否"，图谱里有相关但不支持结论的事实 | 对称矩阵一定可逆吗？ |
  | 图谱未覆盖 | 24 | 计算题和图谱外的事实 | 二阶矩阵 [[1,2],[3,4]] 的行列式等于多少？ |

- **模型**：Qwen2.5-7B-Instruct（硅基流动），温度 0，要求只输出"是/否"或选项字母，不让模型写推理过程。
- **检索只用题干**，不用选项，避免选项里的术语泄露答案。

## 结果

| 方案 | 总体 | 图谱直接可答（28） | 需多跳/推理（29） | 陷阱题（27） | 图谱未覆盖（24） | 平均提示词 token |
|---|---|---|---|---|---|---|
| 不检索 | 95.4% | 100.0% | 100.0% | 96.3% | 83.3% | 67 |
| 向量 RAG | 88.9% | 100.0% | 75.9% | 100.0% | 79.2% | 204 |
| GraphRAG | 96.3% | 100.0% | 100.0% | 100.0% | 83.3% | 214 |
| 混合 | 95.4% | 100.0% | 96.5% | 100.0% | 83.3% | 323 |

实体链接成功率 97.2%（108 题中 105 题靠词典直接链接到了具体实体）。

## 结论

1. **GraphRAG 和不检索没有显著差别。** 96.3% 对 95.4% 只差 1 道题（104 对 103），在 108 道题上属于随机波动。原因是天花板效应：这些教材级的问题，7B 模型本身就基本都会。**这个实验不能证明 GraphRAG 提升了准确率。**

2. **向量 RAG 明显变差，问题集中在多跳题。** 多跳题从 100% 掉到 75.9%（29 题错了 7 题），总体比不检索少对 7 题。逐题看，错误模式很一致：检索回来的句子和问题相关，但都没有直接给出结论，模型就倾向于回答"否"。例如问"半正定矩阵的特征值都是实数吗"，检索到的是"实对称矩阵的特征值都是实数""正定矩阵的特征值全为正"，没有一句提到半正定矩阵，模型答了"否"。

3. **同样的题，GraphRAG 没有这个问题。** 因为图谱里已经把推理结论物化成了边（如"半正定矩阵具有性质：特征值全为实数"），检索到的事实直接回答了问题。这是本实验里图检索相对向量检索最清楚的优势：**不是比不检索更好，而是不会像向量检索那样帮倒忙。**

4. **检索救不了计算题。** 图谱未覆盖的 24 题里，四种方案都只有 80% 左右，有 3 道计算题四种方案全错。这类题需要的是让模型写出计算过程或调用计算工具，而不是检索。

5. **成本**：GraphRAG 的提示词约 214 token，是不检索的 3 倍，和向量 RAG 相当；混合方案最贵（323 token），效果并不更好。

## 局限

- **题目是我在已知图谱内容的情况下编写的**，"图谱直接可答""需多跳/推理"两类题天然对 GraphRAG 有利。
- **题量小**（108 题），1–2 题的差别没有统计意义。上面的结论 2 差了 7 题，相对可靠；结论 1 不可靠。
- **只测了一个模型、一种作答方式**（直接输出答案）。让模型先推理再作答，结果可能不同。
- **向量 RAG 的文档库很小**（142 句），而且和图谱的种子知识同源，不代表真实教材检索的水平。
- **图谱本身有噪声**：例如模型抽取出的"楚列斯基分解的作用对象是矩阵"是不准确的，这次没有造成错题，但换个问法可能会误导模型。

## 下一步值得做的实验

- **换成模型不知道的知识**：给图谱加入模型训练数据里没有的内容（比如自定义的课程体系、虚构的定义），这时不检索的准确率会很低，才能真正测出检索的增益。
- **换更弱的模型**（如 1.5B、3B），看基线不在天花板时 GraphRAG 是否有提升。
- **加大题量并做显著性检验**，或多次重复取平均。
- **让模型先推理再作答**，并对计算题接入代码执行工具。
